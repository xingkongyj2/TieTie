# 贴贴前端迁移：Taro 微信小程序

## 当前方案

主前端使用 **Taro 4.3 + React 18 + TypeScript + Webpack 5**，构建目标为微信小程序。`@tarojs/plugin-html` 兼容已有 JSX 中的 HTML 标签，便于保留原组件、类名、配色、间距和 CSS 动画。`frontend/web/` 保存迁移前的 React 19 + Vite H5 基线；新的小程序代码位于 `frontend/src/`，后端继续使用原 Go 服务。

采用一个小程序页面 `pages/index/index`，页面内继续呈现「我们 / 待办 / 我的」导航和原有弹层。日期、时间、地区等界面沿用原设计；输入和表单提交由 `components/Fields.tsx` 桥接原生事件，滚动容器改用 `ScrollView`。前后台切换通过 Taro 生命周期控制同步，网络请求、存储、剪贴板、附件和图片预览使用小程序 API。

原始角色素材、标题字体和图标几何仍是视觉依据。构建前执行资源准备脚本：头像压缩、SVG 插画转 PNG、生成兼容图标资源，再复制到产物。头像数据仍保存原相对路径，显示时由 `lib/assets.ts` 映射到包内资源。原 CSS 像素数值保留，关闭自动 px→rpx 转换；小程序所需的布局修正集中在 `src/mini.css`。

微信胶囊按钮占用的顶部区域由 `getMenuButtonBoundingClientRect` 留位，内容区继续使用原设计。标题字体在本地 WXSS 中内联，HTTPS 环境同时通过 `loadFontFace` 加载后端内嵌的无损 WOFF 字体（`/api/assets/reminder-titles.woff`），不依赖旧 H5 部署；同目录提供 OFL 许可。

小程序三个主页面顶部显示「我们」「提醒」「我的」，与微信右上角胶囊在同一行，按整个页面水平居中；原来内容区的页面标题行移除，聊天与个人卡片直接从胶囊下方展开，提醒页保留四个分类标签。角色信息入口迁至顶部左侧，标题不会随内容滚动。顶部标题使用稳定的原生节点，切换页面不会重新挂载聊天历史。

提醒页「待办 / 倒计时 / 纪念日 / 贴贴」分类标签整体水平居中。待办没有任何记录时，和其他三个分类共用居中的空提示卡片与留白，仅显示图标、标题和聊天示例，不显示绑定提示或按钮。加载中、请求失败、有历史记录或仅筛选结果为空时，仍显示原有状态和提醒列表。

未绑定时，「我们」直接显示邀请码、复制/分享邀请和绑定表单，无需再经过欢迎提示与「连接彼此」按钮。邀请页沿用自己的顶部留位，使用主页面「我们」标题，不重复展示品牌标题；切换其他主页面后再回来，已填写的对方邀请码保留。通过邀请链接进入时仍自动预填邀请码，绑定成功后直接显示聊天。

Taro 标签适配机制及边界见 [Taro HTML 标签文档](https://docs.taro.zone/docs/use-h5)。使用兼容标签并不表示拥有浏览器 DOM、浏览器默认交互或全部 CSS 能力，因此迁移同时替换了这些依赖。

## 功能对应

| 原功能 | 小程序实现与数据来源 |
| --- | --- |
| 微信一键登录 | 小程序通过 `/api/auth/wechat` 自动创建或恢复账号；JWT 与绑定沿用原后端，H5 保留用户名密码登录 |
| 微信订阅提醒 | 「我的」中用户主动授权；服务端将 AI/手动到期提醒、早晚关怀及纪念日推送到微信，点击进入当前账号对应空间的聊天 |
| 两人空间绑定与解绑 | 沿用邀请码和 `/api/account/*`；邀请码使用微信剪贴板，分享邀请通过小程序页面参数预填 |
| 共享聊天和仅自己可见聊天 | 沿用会话、消息和工具应答接口；消息同步适配小程序请求与前后台生命周期 |
| 图片和文本、Office 附件 | 使用微信选择接口读取原文件，再沿用后端附件协议及大小、数量限制；格式是否可解析仍由原后端决定 |
| 待办提醒 | 保留对象筛选、数量、生命周期、接收者完成权限、恢复、取消、删除和滑动操作；快捷表单保留全部既有重复规则及北京时间校验 |
| 纪念日与倒计时 | 沿用真实列表、置顶与分页接口；新建仍通过聊天自然语言处理 |
| 早安、晚安及纪念日提醒 | 沿用关怀与纪念日提醒设置接口；保留时间弹层、错误提示和天气卡片 |
| 我的资料、头像、地区 | 沿用资料和地区目录接口；保留图鉴、个人资料表单与地区三列选择 |
| 对方印象和 AI 说话方式 | 沿用印象补充、生成状态、失败重试、幂等请求键和设置接口 |

迁移不更改服务端的提醒调度、持久化或两人空间权限。构建成功只确认代码与小程序包可生成，尚不能代替真实账号、真实后端和真机验收。

## 微信登录

小程序登录页顶部水平居中显示「贴贴清单」，根据微信胶囊按钮的真实位置与高度垂直居中，标题和右上角关闭按钮在同一行，并对称留出胶囊区域。中间保留角色图标与窄登录按钮，按钮中是图标与「一键登录」，按钮上下不显示说明文字，不渲染用户名、密码和注册表单。点击后调用 `Taro.login` 获取新的临时 code，传给 `POST /api/auth/wechat`；后端兑换微信身份，首次创建独立账号和邀请码，后续复用同一账号。JWT、资料引导和两人空间继续沿用原流程，原账号密码账号不会自动与微信账号合并。Taro H5 和 `frontend/web` 保留原账号密码登录。

服务端需配置 `WECHAT_APP_ID`（与 `project.config.json` 的 AppID 一致）及 `WECHAT_APP_SECRET`。配置方法见 `backend/.env.example`；不要把 AppSecret 放进 `TARO_APP_*`、小程序源码或构建产物。更新后端后需要重启服务以加载配置和新增身份表，再用微信开发者工具或真机验证真实 code 兑换。前端构建和隔离测试不能替代真实微信登录验收。

微信登录出现「当前服务暂不支持微信登录」时，检查小程序实际连接的服务器是否已部署新版后端，而非只重新构建小程序。旧服务对 `POST /api/auth/wechat` 返回 404；新版服务收到空 JSON 时返回 400 `invalid_wechat_code`，可以用这个无账号创建、无微信兑换的请求检查路由是否已更新。仅接口存在不能确认 AppSecret 配置正确，真实登录仍需真机验收。

## 微信订阅提醒

「我的 → 微信提醒」读取服务端模板与余额，并在用户点击时直接调用 `Taro.requestSubscribeMessage`。保存失败时保留本次授权结果和 requestId，重试保存不会再次申请授权或重复计数。一次性模板明确显示每次授权接收一条提醒，余额以服务端为准。服务端未配置模板时入口显示尚未开通。

推送跳转 `pages/index/index?from=reminder&sessionId=...`。App 前台生命周期与页面加载共同接收冷/热启动参数；未登录时保留跳转意图，登录恢复后切回聊天、关闭弹层并刷新最新消息。只使用当前账号绑定的 sessionId 加载聊天，过期空间或不属于当前账号的链接给出提示。

上线需选择微信公众平台订阅模板并配置后端，见 [后端配置](../backend/.env.example)。当前模板尚未选择，真实消息发送和真机冷/热启动仍需联调；普通订阅授权一次只能发送一条微信消息。

## 尚未接入的微信能力

- **真实语音转写**：保留语音面板和手势状态，但没有配置可用的录音转写服务。释放手势会明确提示改用文字，不会生成模拟识别结果。启用需要选定语音服务并完成录音授权、转写调用和真实结果发送。

## 本地构建与导入

在 `frontend/` 执行，使用 Node.js 22.12 或更高版本：

```bash
npm ci
cp .env.example .env.local # 仅首次；已有文件不要覆盖
npm run typecheck
npm test
npm run build
```

`npm run build` 同时准备资源、输出 `dist/`，并校验页面文件、JavaScript/正则兼容性和主包大小。开发时使用 `npm run dev` 持续构建。`frontend/.env.local` 中的 `TARO_APP_API_BASE_URL` 指定本地 Go 后端：仅模拟器测试可用 `http://127.0.0.1:4173`；真机测试使用 `http://电脑的局域网IP:4173`，改完后重新构建。按 `backend/README.md` 启动本地后端，数据库连接参数也需适合本机运行环境。

微信构建会展开裸 `:first-child` / `:last-child` 选择器，聚焦效果使用组件的 `is-focused` 状态，避免 H5 的 `:has()` 与通配符阻止 WXSS 编译。macOS 上若微信开发者工具安装在默认路径，包检查还会调用其原生 `wcsc` 编译器检查全部 WXSS；其他安装位置可通过 `WECHAT_WXSS_COMPILER` 指定可执行文件。未找到原生编译器时会明确提示仍需在开发者工具中确认编译。

1. 检查 `frontend/project.config.json` 中的 `appid` 与微信后台的小程序 AppID 一致。当前已填写项目的 AppID。开发者工具直接使用 Taro 编译结果，关闭再次转 ES5、样式补全和代码压缩。AppSecret 只用于需要它的服务端微信能力，不要写入前端。
2. 在微信开发者工具中导入 **`frontend/` 目录**。项目配置中的 `miniprogramRoot` 为 `dist/`，不要把 Taro 的 `src/` 当作小程序编译目录。
3. 在开发者工具本地调试设置中临时关闭合法域名校验。手机上的 `127.0.0.1` 指向手机自身，真机测试本地后端时需在 `.env.local` 填写电脑的局域网 IP，后端以 `HOST=0.0.0.0` 启动，并确保手机与电脑在同一 Wi-Fi。若本地后端共用服务器数据库，通过启动环境变量指定本机可连接的 `MYSQL_HOST`，同时设 `BACKGROUND_WORKERS_ENABLED=false`，避免和服务器重复运行后台任务。电脑 IP 改变后需更新前端地址并重新构建。
4. 体验版、正式版构建前明确设置 API 地址。示例地址需替换成自己的服务：

   ```bash
   TARO_APP_API_BASE_URL=https://api.example.com npm run build
   ```

   该变量是公开的 API 基地址，不要包含账号令牌或其他服务端凭据。接口路径已经含 `/api/`，通常基地址只需填写 HTTPS 域名。修改变量后必须重新构建。
5. 在微信小程序管理后台配置 API 的 **request 合法域名**；如使用远程图片或文件下载，也配置对应的 **downloadFile 合法域名**。在开启合法域名校验的状态下验证真机网络。使用有效 HTTPS 证书，具体平台要求以 [微信小程序网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html) 为准。
6. 登录两个实际账号，绑定同一空间，验证消息、资料、提醒和设置的双端同步，再使用开发者工具预览或上传体验版。

`.env.local` 中的 API 地址在构建时写入产物；显式 shell 环境变量可覆盖它。只有完全未配置 API 地址时开发版才回落到本机地址；体验版和正式版要求 HTTPS 地址。无需在前端增加 Qoder 令牌，现有云端凭据继续由 Go 后端管理。

## H5 基线与视觉验收

迁移前版本在 `frontend/web/`，可在主前端目录执行 `npm run dev:legacy` 或 `npm run build:legacy`。Taro 的 H5 目标通过 `npm run dev:h5` / `npm run build:h5` 检查共同组件，但它不是微信原生渲染结果。

`build:h5` 属于生产构建，也需设置 HTTPS `TARO_APP_API_BASE_URL`；日常本机预览使用 `dev:h5`。H5 表单继续使用浏览器控件，微信构建使用原生控件；两者共用业务验证与视觉 CSS。

视觉目标是保持原版样式和特效。验收须以同一账号、同一数据、相近逻辑尺寸比较原 H5 与微信真机：

- 比较三个导航页、四个待办标签、微信登录（H5 为登录/注册）、绑定、引导页、资料表单和各个弹层的字号、留白、渐变、圆角与图标颜色。
- 检查长内容滚动、横向天气表格、地区三列滚动、键盘弹出、输入光标、底部安全区和窄屏布局。
- 检查伙伴入场、装饰入场、底栏切换、弹层进出、提醒滑动、开关过渡、加载与语音面板动画。
- 检查空列表、加载失败、保存失败、慢网络、重复点击、前后台切换及解绑后重新绑定，确认状态与数据不会混入其他空间。

待办装饰拆成三个透明全画布图层，分别保留原变换中心及 0.25 / 0.4 / 0.55 秒错峰入场。微信的字体、CSS 支持、图片渲染和系统键盘与浏览器仍存在平台差异。需要在开发者工具和至少一台 iOS、一台 Android 真机上对齐，不能仅凭 TypeScript 或构建通过宣称所有像素、字体与动画时序完全一致。

## 已完成的验证与剩余边界

- `npm ci`、TypeScript 检查、45 项前端测试、`go test ./...`、微信构建和保留的 H5 构建通过。微信构建末尾自动检查主包不超过 2 MiB；当前 2009 KiB / 2048 KiB，后续增加资源须继续检查包体积。
- 浏览器以 390 × 844 逻辑尺寸和相同模拟接口数据比较原 H5 与 Taro H5 的登录、我们、待办、我的、资料弹层；验证登录、真实请求格式的消息发送、待办标签切换和弹层关闭，未出现页面运行异常。这些模拟数据仅用于隔离回归，没有写入实际账号。
- 小程序聊天记录按批次挂载，保留完整历史。Taro 原生运行时用 1,200 条消息验证追加批次和稳定页面层级：约 5.4 MB 的完整树拆为 400 个批次，最大追加约 14 KB；切换导航和弹层不会重新下发整份历史。单条超大消息、已有大量消息同时更新及低性能真机上的渲染仍需专项验证。

当前已配置 AppID 并安装微信开发者工具，尚未完成微信真机验收。原生字体、布局、动画、键盘与双账号同步的最终验收仍须按上面的步骤完成；H5 对照和构建通过不能替代这一项。
